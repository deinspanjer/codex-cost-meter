Proposal schema version 1 (separate from catalog schema 1 and display version):
The JSON envelope has exactly proposal_schema_version:1, catalog_schema_version:1, operations:[], evidence:[], coverage:[]. coverage is a list of unresolved/unverified coverage statements; empty means you assert complete requested coverage. No verification bypass fields are accepted. Limit: 4096 operations, 256 evidence records, 8 MiB file.
Each operation has id (unique string), group (nonempty atomic group name), kind (add, replace_value, remove, move), target, expected, replacement (or null), evidence_ids (nonempty list referencing evidence), and date_basis (nonempty reasoning string).
All dependent edits share a group. Independent point removals are unresolved: pair a removal with a supported replacement in the same model/tier/context history and group, or use move. Stale preconditions or failed evidence reject that entire group while unrelated groups can proceed. Overlapping targets are unresolved, never reordered to satisfy preconditions. Preconditions describe exact current EFFECTIVE values at the target date, not an old file revision.
Point keys: {model: exact string, tier: standard|fast|ultrafast, context: short|long, effective_from: YYYY-MM-DD}. Rates: {input: number|null, cached_input: number|null, cache_write_input: number|null, output: number|null}. Omitted cells are unknown. All known rates must be finite and nonnegative.
Target objects:
  {"type":"point","key":KEY} — effective point, removal tombstones an underlying embedded key.
  {"type":"overlay_point","key":KEY} — remove only an external override, revealing embedded pricing.
  {"type":"tombstone","key":KEY} — remove a tombstone, revealing embedded pricing.
  {"type":"threshold","model":"exact-id"}
  {"type":"proxy","proxy":"exact-id"}
Expected objects: {"type":"absent"}, {"type":"rates","value":RATES}, {"type":"threshold","value":INTEGER}, {"type":"proxy","value":[{"effective_from":"YYYY-MM-DD","target":"exact-id"}]}, or {"type":"tombstone"}. First proxy point may omit effective_from.
Replacement objects: {"type":"point","key":KEY,"rates":RATES}, {"type":"threshold","threshold":INTEGER}, {"type":"proxy","points":[PROXY_POINT]}, or null for removal.
Add requires an unoccupied point key and the prior effective rate (or absence). Replace/remove/move require the exact key to exist. Move changes only the effective date and atomically removes the old key, adding the new unoccupied destination; it never silently overwrites custom destinations. Threshold/proxy add expects absence; replacement/removal expects the old effective value. Remove overlay_point requires that external point; remove tombstone expects a tombstone. Unknown kinds, versions, malformed references or shapes fail the proposal.
