# Release approval rubric

Approve a candidate only when its requirements and approved plan trace to owned changes, its validation is current and passing, and its user, developer, and release documentation matches the shipped behavior.

Reject when the candidate has incorrect ownership, duplicated responsibility, speculative compatibility layers or abstractions, missing focused behavioral tests, disproportionate module or dependency growth, incomplete validation, or unresolved requirement divergence. Require every accepted follow-up to be explicit, bounded, and recorded in `TODO.md` or an ADR.
