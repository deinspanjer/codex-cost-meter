# Updating model pricing

[Developer guide](../DEVELOPERS.md)

Pricing is an offline, reproducible estimate of API token list cost, not a Codex subscription bill. The executable embeds `data/model-prices.json`; editing that file affects newly built binaries. Reports recompute prices from cached usage facts, so a catalog-only update needs no cache-version bump or cache deletion. A parser classification change (such as recognizing a previously unsupported tier) requires an analysis-cache version bump so old classifications are reparsed.

Inspect a built executable's catalog with `codex-cost-meter rates`, optionally `--model <EXACT_ID>`, `--as-of YYYY-MM-DD`, or `--json`. This reads no session storage and uses the same effective-date and proxy lookup as cost estimation. It preserves unknown components and exposes all catalog context bands, including unknown long-context cells for otherwise listed tiers. JSON distinguishes `catalog_as_of` (review date), `effective_on` (requested selection date or null for latest), each row's price `effective_from`, and `proxy_effective_from`. It exports default 30-minute write rates only. See the [user guide](../USERS.md#show-the-rate-table).

## Evidence and historical meaning

Use official [API pricing](https://developers.openai.com/api/docs/pricing), the exact model's documentation, the [API changelog](https://developers.openai.com/api/docs/changelog), dated [OpenAI launch announcements](https://openai.com/news/), archived copies of those official pages, and the [Fast-mode guide](https://developers.openai.com/api/docs/guides/fast-mode). Previous sessions and research notes explain decisions and point to sources; reopen those sources before treating them as current evidence. Third-party catalogs and search snippets are discovery aids, not pricing authority.

Rates are USD per million tokens. Each dated price point holds uncached input, cached input, cache-write input, and output rates, with separate Standard/Fast/Ultrafast and short/long-context cells. Gross input determines the context band; the chosen band prices the whole request. Cache reads and writes are subtracted from gross input before charging uncached input. Reasoning is already included in output. Cache-write cells currently represent the default 30-minute lifetime; rollout counters do not distinguish 12-hour writes. Do not apply a single lifetime setting to mixed-lifetime API usage or claim those writes are fully supported. Never infer a global Fast multiplier or cache discount from another model.

`as_of` records when the catalog was reviewed; `effective_from` records when a rate applies. Preserve older points when prices change. Correct an erroneous historical point only with evidence supporting the correction, documenting the previous assumption. For a new model, a dated launch announcement plus matching model pricing can support a launch-date estimator boundary; record that basis. Before falling back to an observation date, search dated launch announcements, the API changelog, and archived captures of the official pricing/model pages around launch and suspected changes. Retrieve the archived content, not just the archive index. Distinguish the announcement date, snapshot identifier date, API availability date, capture date, and any explicit rate-change date. A near-launch capture can corroborate a launch-date estimator boundary; disclose that inference rather than claiming an exact billing cutover. Only if this historical search leaves the start unsupported should an older model's newly discovered rate use the observation date, with the search and remaining gap recorded. Do not invent future price changes from a promotion's minimum duration. Dates are day-granular estimator boundaries, not proof of an account's exact billing cutover.

A missing rate is unknown, not zero. Use `null`/absent optional cells for unavailable components or tiers; retain known cost and incomplete-result behavior. Keep exact model IDs and explicitly evidenced proxy histories. A successor model is not an alias for its predecessor. See the [Auto-review evidence](research/codex-auto-review-pricing-evidence.md) and [Fast attribution evidence](research/fast-mode-attribution-evidence.md) before changing those boundaries. Requested/applied tier telemetry does not establish the actually served tier.

## Procedure for maintainers and agents

1. **Establish scope.** Inspect the working tree, catalog, pricing implementation/tests, and previous refresh evidence. Review every existing model's latest cells and new relevant Codex models; do not expand into unrelated image, audio, tool-call, or subscription billing. Record models retained without fresh verification rather than claiming a full audit.
2. **Fetch evidence before editing rates.** Open current official pages, including the changelog since the last review. Record retrieval date, exact model ID, tier, context threshold, all four token rates, effective-date evidence, and source URLs in a concise `docs/research/` refresh note. Inspect labeled Standard, Fast, and Ultrafast tables: flattened pages can mix Batch/Flex prices or omit collapsed rows. Use the official `.md` page or browser table when extraction loses labels. A row missing from the headline table is not proof of removal or a price change: check collapsed rows and the exact older model page. Resolve disagreements against exact model pages and dated announcements; leave genuinely unresolved cells unchanged/unknown and explain them.
3. **Edit the catalog.** Add explicit rate cells and increasing history dates; update `as_of` and source provenance. Preserve older models and proxies. Thresholds currently live per model, outside its history: changing a threshold affects every date. If a threshold itself changed historically, the schema needs a separately reviewed correction; do not silently rewrite history. When adding a previously missing threshold, verify that dates without long-context cells become incomplete rather than retaining a falsely complete short-context estimate.
4. **Verify behavior.** Add or extend the smallest pricing test covering the affected date boundary, threshold and threshold-plus-one, Standard/Fast, and independently calculated component costs. Include distinct cache-read rates for similarly named models. Preserve coverage for unknown rates and historical/proxy lookup. Run `just test-filter pricing::tests`, then `just check`, and `git diff --check`. Inspect a synthetic CLI report if output/provenance changes require it. Do not add tests for static documentation wording.
5. **Explain the result.** Update the refresh note with changes, unchanged/unverified coverage, unresolved evidence, and validation outcomes. Update `USERS.md` and `[Unreleased]` in `CHANGELOG.md`; link to the evidence instead of duplicating large rate tables in user guidance. Review the final diff for accidental historical repricing and unsupported assumptions, explicitly checking that new thresholds cannot silently apply short-context rates to historical long-context usage, then revise this procedure if executing it revealed a material gap.
6. **Deliver within the requested scope.** Build the updated executable (`cargo build --locked --release`). A requested release additionally follows the [release and packaging guide](releases.md). Publishing, installing, or rewriting existing titles is a separate action unless included in the request. For an authorized title repricing campaign, use the new binary and one fixed `--reprice-before` cutoff across bounded batches, as described in [ADR 0003](adr/0003-use-session-index-updated-at-as-the-high-water-mark.md); do not move the cutoff between batches.


## External catalog schema

External schema 1 is a UTF-8 JSON object at the user-home path described in [USERS.md](../USERS.md#local-pricing-files). Required fields are `schema_version: 1` and nonempty display `version`; optional `label` is user text. Omitted `base` overlays embedded data; `base: "none"` selects standalone data. All collections default to empty:

- `points`: flattened keys `model`, `tier` (`standard`, `fast`, `ultrafast`), `context` (`short`, `long`), `effective_from` (ISO date), plus `rates` and optional `basis`/`source`.
- `rates`: optional/null `input`, `cached_input`, `cache_write_input`, `output`, in USD per million tokens. Every known rate must be finite and nonnegative. A replacement is a whole rate object, never a cellwise inheritance.
- `removals`: the same flattened key plus optional `basis`/`source`; these are tombstones for embedded points. Duplicate point/removal keys are invalid.
- `thresholds`: `{ "model": "exact-id", "threshold": 272000, "basis": "custom" }`. A null threshold removes the existing threshold. Thresholds are model-wide across history.
- `proxies`: `{ "proxy": "internal-id", "points": [{ "effective_from": "2026-11-01", "target": "exact-id" }], "basis": "custom" }`. An empty points array removes the proxy; the first proxy point may omit its date. Dates must increase and targets must exist after merging.

Point dates select rates independently for each tier/context. Unknown components stay unknown. Basis defaults to custom; source attribution is descriptive and does not restrict deliberate manual values. Each invocation reads/merges once and shares the result for all valuation. Normal valuation does not fetch sources. Cached rollout facts contain no frozen pricing, so this change needs no analysis-cache version bump.

## Installed refresh and researched proposals

The installed current-data mode deliberately differs from the maintainer historical procedure above. `pricing refresh` fetches bounded current official Markdown, emits typed schema-1 operations in memory, and verifies citations against those same fetched bytes. It does not research changelogs, HTML, or archives. Only explicitly labeled cells are extracted; moved pages, incomplete labels, unsupported units, unknown thresholds, network failures, and uncovered model/tier/context combinations produce partial coverage. Existing thresholds and proxy histories are retained and explicitly reported as not freshly verified. For a new model, both bands remain unresolved unless a shared flagship cutoff and supported table rows establish which prices apply. New values without explicit cutover evidence start at the UTC retrieval date with observed basis. Old values remain before that boundary; new models remain unknown. Unchanged values create no new point. Occupied same-day differences remain unresolved.

`pricing refresh --from` is another input to the same validator and activation path. It reads at most 8 MiB, accepts proposal schema 1 and catalog schema 1, and independently fetches every citation. Sources are bounded by request/count/body/whole-run limits; redirects must remain within the official-source policy, and archived captures must retain original official-page identity. Conservative visible-text normalization preserves prices, dates, signs, units and labels. An excerpt match does not certify interpretation: affected model/tier/context and replacement values must also be supported, with date reasoning exposed for review. Unsupported representations stay unresolved. Imports cannot assert trusted same-run acquisition or official verification. Accepted imported changes carry researched basis.

The binary bundles the complete proposal contract and examples in `pricing prompt`. Envelope fields are `proposal_schema_version`, `catalog_schema_version`, `operations`, `evidence`, `coverage` (unresolved/unverified statements). Every operation supplies `id`, atomic `group`, `kind`, typed `target`, exact `expected` effective value or absence, optional `replacement`, `evidence_ids`, and `date_basis`. Kinds are `add`, `replace_value`, `remove`, `move`; targets are `point`, `overlay_point`, `tombstone`, `threshold`, `proxy`. A point's key includes exact model/tier/context/date. Missing rate cells stay unknown. Add at a new date checks the prior effective value, not merely whether that date key is absent. Replace/remove/move require an existing key. Moves reserve their destination and remove the source atomically. Conflicting targets, custom destination conflicts and failed preconditions remain unresolved; independent groups may proceed. Groups validate resulting threshold and proxy references before acceptance. Imports reject groups targeting custom points, effective custom prices, custom overrides/tombstones, or standalone catalogs; users can edit these manually.

Removing `overlay_point` reveals any underlying embedded price; removing effective `point` creates a tombstone when needed. Removing `tombstone` reveals the embedded point. Threshold/proxy removals persist explicit overrides so embedded values do not silently return. Imported point removals require a supported replacement in the same model/tier/context history and atomic group; moves combine those halves directly. Every member must pass its own preconditions and evidence checks. Independent removals remain unresolved for manual editing. No operation follows merely from absence in current documentation. Results expose dates, before/after values, evidence and reasoning; catalog storage retains only compact basis/source metadata. No excerpts, retrieval times, source downloads, origin tracking, revision archive, or backups are stored with active pricing.

Generated points (`official`, `observed`, `researched`) are pruned sequentially only when merged effective history with and without them is equal at every date. Embedded November 1=A plus observed November 6=A is redundant; embedded October 1=A plus overlay October 15=B and November 6=A is not. Multiple removals must remain collectively equivalent. Custom and standalone points are excluded. When an official or observed point at D differs from embedded effective pricing and embedded `as_of >= D`, report an unresolved conflict without proposing correction. An older embedded review emits no such conflict. Researched corrections are excluded from this conflict check on subsequent runs, including for models absent from embedded data; they remain generated for history-preserving pruning. This intentionally permits generated boundaries to mask future maintenance changes until explicit researched/manual resolution.

Normal valuation remains offline. The command loads one snapshot before session/title mutation; external files follow the platform user's home, not a selected Codex home. A unique `.model-prices.tmp-` file is written, finished and closed in the destination directory. The destination's reviewed bytes/absence are checked immediately before `std::fs::rename`; replacement never deletes the destination first. Reset uses the same final check before deletion and can remove invalid schemas. The accepted check-to-action race permits lost concurrent updates; it is not serialized. Handled failures remove the temporary file; startup removes only matching files older than one hour. There is no migration engine; delete/reset/regenerate incompatible data or perform a user-managed researched merge.
## Flagship context thresholds

Refresh accepts a single standalone short/long input-token definition in the bounded flagship pricing block. It applies to the block's matching tier tables, not other product sections; a qualifier inside a model cell applies only to that row. Ambiguous definitions or an unrecognized block boundary cannot onboard a model.
