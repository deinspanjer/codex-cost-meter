# v0.1 macOS Reporting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `codex-cost-meter v0.1.0` as one ad-hoc-signed macOS Universal 2 archive that reports cost and usage for an exact Codex thread ID without mutating Codex state.

**Architecture:** One Rust package produces one distributed binary. A bounded JSONL reader feeds rollout discovery and analysis; reporting combines those results with the embedded price catalog and optional session-index display name, then renders human or JSON output. CI tests both macOS architectures and assembles the final Universal 2 artifact only for an intentional version-changing merge.

**Tech Stack:** Rust 2024 on stable Rust 1.97.1, `clap`, `serde`, `serde_json`, `time`, `thiserror`, `tempfile`, `just`, Python 3 standard-library developer release tooling, GitHub Actions, `lipo`, and native `codesign`.

## Global Constraints

- Support macOS 14 or newer on `aarch64-apple-darwin` and `x86_64-apple-darwin`.
- Keep one Cargo package and one distributed `codex-cost-meter` binary; do not add empty future platform modules.
- v0.1 is read-only: no SQLite dependency, title mutation, scheduler, installer, or uninstaller.
- Default Codex home resolution is explicit `--codex-home`, then `CODEX_HOME`, then `~/.codex`.
- Do not follow directory symlinks; bound each JSONL record at 16 MiB; no on-disk input may panic the process.
- Preserve incomplete results visibly instead of guessing or silently omitting unreadable or unattributed usage.
- Tests use isolated temporary Codex homes, table-driven cases, and Rust's default parallel execution.
- Use direct tool calls for builds and tests; do not spend an agent turn merely to run a command. Route Tasks 1-8, focused code review, and routine verification to `gpt-5.6-terra`. Reserve `gpt-5.6-sol` for orchestration, architectural ambiguity, release judgment, storage-accounting risk, and failures Terra cannot resolve from concrete evidence.
- Luna is not currently selectable and is not a plan dependency. If it becomes available during execution, first calibrate it on one deterministic format/build/test packet; use it only for similarly mechanical packets whose result is independently established by command output.
- Every task uses TDD, runs its focused tests before broader checks, and produces one independently reviewable commit.
- Before release, uplift durable content and remove all mechanical files under `docs/superpowers/` from the final tree.

## Pre-execution accounting gate
