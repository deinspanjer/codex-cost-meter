# v0.2 macOS Title Updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.2.0 with safe, configurable macOS title updates in the existing Universal 2 binary.

**Architecture:** Keep one crate. Extract shared session-index state and a reusable report context, add a pure title formatter, then add one update orchestrator that owns SQLite selection, the process lock, and the accepted SQLite-then-JSONL write sequence. CLI integration remains thin and scheduling stays out of scope.

**Tech Stack:** Rust 2024 on 1.97.1; existing clap/serde/serde_json/thiserror/time/tempfile; rusqlite 0.40.2 with default features disabled and bundled SQLite enabled; standard-library filesystem locking.

## Global Constraints

- Dry-run is the default; only `--apply` mutates Codex state.
- Only rollout roots are eligible, including explicit selections.
- Update SQLite `title` and `name`, commit, then append and synchronize `session_index.jsonl` while one process lock remains held.
- Validate only required `threads` columns; unrelated schema additions and higher `user_version` values remain compatible.
- Default title format is `cost,total-tokens` at 65 Unicode scalar values; at least one metric is required.
- Build the rollout index and price catalog once per update run.
- No scheduler, daemon, runtime price file, Windows/Linux mutation, update JSON mode, extra crate, or speculative platform interface.
- Tests use temporary homes, behavior-class tables, and parallel execution unless a real shared resource requires serialization.
- Temporary specification and plan files must be absent from the final release tree.

---

## File map

- `src/session_index.rs`: shared bounded session-index parsing, latest entries, and durable append.
- `src/report.rs`: reusable `ReportContext`; no title-mutation ownership.
- `src/title.rs`: metric list and pure bounded title composition.
- `src/update.rs`: lock, SQLite contract, selection, orchestration, apply/recovery errors.
- `src/cli.rs`: update argument contract and validation/conversion.
- `src/main.rs`: dispatch and sanitized human update output.
- `tests/update_cli.rs`: smallest end-to-end update command contract.
- `Cargo.toml` / `Cargo.lock`: bundled rusqlite dependency.
- Durable docs and changelog: user/developer behavior and release record.

- [ ] **Step 1: Write failing append-repair tests**

Start `session_index.jsonl` with a truncated final JSON object. Append a valid update and assert a separating newline exists, the new record is latest, all bytes were flushed, and one shared RFC3339 timestamp is used for a batch.

- [ ] **Step 2: Implement durable append**

Open the index read/write/create, seek to the final byte, add a newline only when needed, serialize one compact JSON object per update, call `flush`, then `sync_all`. Map open, seek, write, flush, and sync failures to typed index errors.

- [ ] **Step 3: Write failing apply and rollback tests**

Assert a successful apply writes identical titles to SQLite `title`, SQLite `name`, and latest index entries. Cause a SQLite constraint/lock failure and assert no index append occurs.

- [ ] **Step 4: Implement the accepted write sequence**

Compute all proposals first. In one SQLite transaction, update by ID and require exactly one changed row per proposal; commit; then append all index records. Return an error if the append fails after commit.

- [ ] **Step 5: Cover the cross-store interruption and recovery invariant**

Make an existing index readable but non-writable, run apply, and assert SQLite committed while the index did not advance. Restore write permission and rerun; assert both stores converge. Add a narrow error-classification test using `io::Error::from_raw_os_error(28)` so disk-full remains a stable actionable category without requiring a special filesystem.

- [ ] **Step 6: Cover concurrent exclusion**
